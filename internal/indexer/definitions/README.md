# Определения трекеров

Файлы `*.yml` в этом каталоге — определения Cardigann из
[Prowlarr/Indexers](https://github.com/Prowlarr/Indexers), каталог `definitions/v11`
(версия — в файле `SOURCE`). Не правьте их вручную: они перезаписываются командой

    scripts/update-definitions.sh

`extra/` — определения, которые поддерживает Vault (их скрипт не трогает, при
совпадении id они важнее файлов Prowlarr):

- `rutracker.yml` (`rutracker`) — RuTracker со входом по логину и паролю;
- `rutracker-org-cookie.yml` (`rutracker-org-cookie`) — RuTracker со входом по cookie.
  Оба основаны на [msergein/ru-cardigann-yml](https://github.com/msergein/ru-cardigann-yml).

Импорт из Prowlarr берёт определение индексатора из `Definitions/Custom` рядом с
`prowlarr.db`, затем из вшитых и пользовательских, а если его нет и там — из
`Definitions/<id>.yml` (то, что Prowlarr скачал сам, например `rutracker-cookie` —
«RuTracker.org (cookie)»); файлы Prowlarr копируются в `DataDir/definitions`.

Пользовательские определения кладутся в `DataDir/definitions/*.yml` и важнее вшитых.

Лицензия: репозитории-источники не указывают лицензию; определения — описания
публичных сайтов в формате Cardigann (как в Jackett/Prowlarr, GPL-3.0), используются
здесь для личного некоммерческого использования вместе с Vault.

## Расширения Vault для загрузки

Блок `download` понимает три ключа сверх Cardigann (для своих определений в
`DataDir/definitions`):

- `direct: true` — сайт отдаёт сам файл (электронную книгу), а не торрент. Релизы такого
  источника — прямые загрузки, как у OPDS-каталога: ищутся только для книг и комиксов,
  скачиваются в библиотеку без торрент-движка (до 500 МБ). Ссылка релиза должна вести на
  сайт определения, сам файл может лежать на другом хосте.
- `submit: true` у селектора — селектор находит `<form>`, и Vault отправляет её (метод,
  `action`, поля формы), а не читает ссылку.
- `follow:` у селектора — следующие шаги: страница, куда ведёт селектор (ссылка или
  отправленная форма), загружается, на ней ищется `follow[0]`, и так далее. Последний шаг
  ведёт к файлу (или к торренту/магнету — `submit` и `follow` работают и для торрентов).

Запросы источника с `direct` (страницы, шаги, формы, редиректы, сам файл) не ходят в
домашнюю сеть и на сам сервер, пока в настройках источника не включено «Разрешить адреса
домашней сети»: адреса определяет страница сайта. Редиректов не больше 5, с https на http
нельзя. Заголовки `download.headers` уходят и в шаги, и в запрос файла. Файл качается до
10 минут и обрывается, если данные не идут минуту; в библиотеку попадает, только если его
первые байты похожи на формат из имени (EPUB/CBZ — ZIP, PDF, FB2, MOBI, CBR, CB7).

Отправка формы упрощена: не отправляется имя нажатой кнопки, `multipart/form-data`
уходит как urlencoded, поля с атрибутом `form="…"` вне формы не учитываются.

```yaml
download:
  direct: true
  selectors:            # варианты по порядку: сначала EPUB, потом PDF
    - selector: form:has(input[name=filename][value$=".epub"])
      submit: true
      follow:
        - selector: meta[http-equiv="Refresh"]
          attribute: content
          filters: [{name: regexp, args: "url=(.+)$"}]
```
